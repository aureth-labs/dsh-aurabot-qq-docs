# 语音

「语音」页面控制语音发送、试听和语音识别。具体合成引擎见[语音合成](tts.md)。

默认引擎为 `edge-tts`，安装在 AuraBot 的 Python 虚拟环境中。Windows 上可使用系统中文语音作为后备。

## 启用语音

1. 在「说话 → 语音」中安装 `edge-tts`。
2. 开启语音并选择音色。
3. 生成试听音频。
4. 保存配置。

试听只验证合成过程，不经过平台发送。试听成功但平台没有语音时，应检查发送权限和平台连接。

## 发送策略

关闭语音时只发送文字。开启后是否使用语音由配置、心情和回复内容决定；用户明确要求语音时，也可触发合成。

## 可用引擎

| 类型 | 说明 |
| --- | --- |
| `edge-tts` | 默认在线合成服务 |
| 本地模型 | CosyVoice、GPT-SoVITS 等 |
| 自定义 HTTP 接口 | 配置地址、方法、请求头和请求体 |

自定义接口中的 `{text}` 会进行转义，`{reqid}` 在每次请求时更新。返回 JSON Base64 数据时可解码为音频。

## 音色转换

「语音条变声」可在 TTS 后使用[翻唱](cover.md)中的 RVC 音色进行转换。RVC 环境不可用或转换失败时，仍发送原始 TTS 音频，并在日志中记录原因。

## 语音识别

收到的语音先尝试使用 QQ 的 `fetch_ptt_text` 转写，失败后尝试 DSH 的 `speechToText`。桌宠对讲也使用同一套 ASR 能力。

## 排查

| 现象 | 检查项 |
| --- | --- |
| 试听无声音 | `edge-tts` 安装状态和网络连接 |
| 试听正常但平台不发送 | 语音开关、权限和平台连接 |
| 自动改为文字 | 日志中的合成或发送错误 |
| 音色转换失败 | 翻唱环境和当前音色 |
| 无法识别收到的语音 | 「语音」页面的 ASR 自检 |
