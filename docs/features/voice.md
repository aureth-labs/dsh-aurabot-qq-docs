# 语音

「语音」页管的是**要不要发语音条**，不是「用哪个引擎」。引擎在 [TTS](/features/tts)。

默认是 `edge-tts`（微软在线朗读，免费、要联网），装在插件自己的 Python 虚拟环境里，Windows / Linux / macOS 都行。Windows 上装不上时用系统自带中文语音兜底。

## 打开语音

1. 面板「说话 → 语音」→ 点「安装 edge-tts」
2. 打开语音
3. 选一个音色，点「生成」试听
4. 保存

试听能出声就通了。**试听不经过 QQ**，所以试听行、语音条不行的，问题在发送或权限，不在合成。

## 她什么时候发语音

| 情况 | 行为 |
| --- | --- |
| 语音关着 | 只发文字 |
| 语音开着 | 由心情和回复内容决定（心情明显时概率更高） |
| 你明确要求「说给我听」 | 会念 |

不是每条都转语音——那样又吵又费额度。

## 三种引擎

| 引擎 | 说明 |
| --- | --- |
| `edge-tts` | 默认，一装就有 |
| 本地模型 | CosyVoice、GPT-SoVITS，在「本地接口」页接 |
| 任意 HTTP 接口 | 「其他 HTTP 接口」自己填地址、方法、请求头、请求体 |

::: tip 「其他 HTTP 接口」能接什么
`{text}` 自动转义，`{reqid}` 每次换新。所以火山、阿里、讯飞这类要鉴权的云 TTS 也能直接接；返回 JSON（base64）会自动解成音频。

想换成豆包 / 千问这种成品模块，见 [TTS：换一个嗓子](/features/tts)。
:::

## 语音条变声

「语音」页有「语音条变声（用翻唱音色）」：先 TTS，再用[翻唱](/features/cover)里导入的 RVC 音色变一次声——**说话和唱歌是同一个声音**。

前提是翻唱环境已经装好。变声失败会用 TTS 原声发出，不影响发送，原因写在日志里：

```text
翻唱模块没就绪，这一轮没变声（原声）
翻唱里没有音色「X」，这一轮没变声（原声）
变声失败，用原声：<具体报错>
```

## 她听你说话

别人发来的语音她会先转成文字再听（ASR）：

```text
先用 QQ 自带的语音转文字（fetch_ptt_text）
   └─ 不行再用 DSH 的 speechToText
```

「语音」页有语音识别自检，看它是不是就绪。ASR 没就绪时，发语音给她只会被当成一条空消息。

桌宠的对讲、语音通话都依赖同一套 ASR。

## 排错

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 试听没声音 | `edge-tts` 没装好，或没联网 | 重新点「安装 edge-tts」，看输出 |
| 试听行、QQ 里不发 | 语音开关没开，或权限没过 | 「语音」+「权限」各看一眼 |
| 语音发不出来 | 自动改发文字 | 面板日志会写原因；先确认 TTS 那条通 |
| 声音是机器人腔 | 用着内置音色 | 换音色，或上 TTS |
| 每句都变声失败 | 翻唱选了音色但环境没就绪 | 「翻唱」页看环境状态，或先不选 |
| 发语音给她没反应 | ASR 没就绪 | 「语音」页的识别自检查原因 |
