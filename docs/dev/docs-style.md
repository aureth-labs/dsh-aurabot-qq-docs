# 文档写作规范

这份规范只管**本仓库的文档**（`docs` 分支下的 Markdown）。目标很朴素：读起来不别扭，
机器处理也不出岔子。

## 中英文混排

**中文和英文、数字之间加一个空格。**

| 别写 | 写成 |
| --- | --- |
| 用TypeScript写插件 | 用 TypeScript 写插件 |
| 装好DSH后 | 装好 DSH 后 |
| 版本号1.2.0 | 版本号 1.2.0 |
| 第3步 | 第 3 步 |

例外：全角标点前后不加空格，中文引号、括号内部不加。

## 标点

- **中文句子用全角**：，。；：？！「」（）《》
- **英文、代码、URL 用半角**：`, . ; : ? ! " " ( ) < >`

链接和 URL 不要紧贴中文标点：

| 别写 | 写成 |
| --- | --- |
| 详情见https://example.com/a。 | 详情见 [示例站](https://example.com/a)。 |
| 参数填true即可 | 参数填 `true` 即可 |

## 代码与命令

- 行内代码、文件名、字段名、命令一律用反引号：`npm run check`、`package.json`、`aurabot.artifact`
- 多行命令用三个反引号的代码块，并标语言：`bash`、`powershell`、`json`、`ts`、`text`
- 路径用正斜杠，或明确写出平台

### 代码块必须标语言（MD040）

所有围栏代码块都要在开头三个反引号后面写语言，**没有例外**：

| 内容 | 标什么 |
| --- | --- |
| 命令 | `bash`、`powershell` |
| 代码 | `ts`、`js`、`json`、`md` |
| 目录树、流程图、报错原文、纯文本 | `text` |

目录树也属于纯文本，不能空着：

```text
repo/
└─ docs/
   └─ dev/docs-style.md
```

对应 markdownlint 的 `MD040/fenced-code-language` 规则。

## 术语统一

同一个东西只用一个叫法，别换着花样说：

| 统一用 | 不要写成 |
| --- | --- |
| 插件 | 扩展、模块（**模块是插件包里的一类东西，不是同义词**） |
| 宿主 | 主框架、主程序、本体 |
| 面板 | 后台、管理页、控制台 |
| 市场 | 商店、索引仓库（仓库指具体的 Git 仓库） |
| 镜像源 | 索引源、API（`market.json` 才是索引本身） |

产品名按官方大小写写：`TypeScript`、`JavaScript`、`DeepSeek Harness`、`AuraBot`、
`OneBot v11`、`SnowLuma`、`VitePress`、`GitHub`。

## 结构

1. 每页开头一段说清「这页解决什么问题」，别从背景历史讲起
2. 能用表格就不用长段落罗列
3. 步骤类内容用有序列表，一步一个动作
4. 结论在前，理由在后；不要用「请注意」「建议咨询专业人士」稀释结论

## 不确定的东西怎么标

- 版本差异：写「以你装到的那版为准」
- 待确认：标 `[存疑]`
- 没验证过：直接写「没验证过」，不要写成肯定句

## 链接写法

两种链接区别很大，别混：

| 指向 | 写法 | 例子 |
| --- | --- | --- |
| 站内页面 | 以 `/` 开头，不带 base 前缀 | `/guide/install` |
| `public/` 里的静态文件 | **绝对地址** | `https://aureth-labs.github.io/dsh-aurabot-qq-docs/llms.txt` |

第二条是踩过的坑：VitePress 只给页面补 `base`，`public/llms.txt` 是原样拷贝的静态文件，
写 `/llms.txt` 会跳到域名根目录，线上就是 404。
