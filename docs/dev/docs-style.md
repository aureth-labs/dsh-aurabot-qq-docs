# 写作规范

本站以简体中文作为唯一编写语言。以下规则约束中文正文、技术名称、代码和 Markdown 结构。文档用于帮助读者完成具体操作，句子应当清楚、简短，不替产品宣传，也不重复同一结论。

## 适用范围

- 当前只维护简体中文，不建立翻译分支，不接入 Crowdin 一类翻译平台，也不维护译文记忆库。
- 不要求把中文内容逐句译成英文。英文只出现在产品名、协议名、代码、路径和没有通行中文名称的术语中。
- 将来若启动本地化，另行起草本地化规范，覆盖术语一致性、占位符、复数形式和审校流程；不要在本页零散添加翻译规则。
- 本页只管「怎么写」，不管「写什么」。内容范围由各章节的定位决定。
- 与 [术语表](glossary.md) 冲突时，以术语表为准；术语表没有覆盖的名称，先补术语表，再回到正文使用。

## 文风

- 先说结论，再写条件和步骤。
- 一页只解决一类问题。背景、安装方法、配置说明和故障排查不要挤在同一页。
- 能直接说明事实时，不使用比喻、口号或反问。
- 不写「简单来说」「不难发现」「你一定遇到过」「赋能」「丝滑」「完美」「最佳实践」等空泛表述。
- 不用大量粗体制造重点。只有默认值、限制和容易误操作的地方需要强调。
- 列表中的项目采用相同句式。步骤写动作，表格写属性，说明文字解释原因。
- 页面顺序由侧栏决定，不在文末另写「下一步」或「延伸阅读」。
- 功能尚未实现时，明确写「规划中」或「待确认」，不使用确定语气描述设计稿。
- 同一页中的同一概念使用同一个名称，不为了变化句式而替换同义词。

| 不推荐 | 推荐 |
| --- | --- |
| 她的大脑，想聊就聊 | 模型服务负责生成回复 |
| 一句话记住，永不绕晕 | AuraBot 是 DeepSeek Harness 的插件 |
| 只需三步，丝滑上线 | 按以下顺序完成配置 |
| 不会让消息石沉大海 | 请求失败时记录错误并返回提示 |

### 转述而非逐词替换

界面文案、设计稿、上游英文文档和聊天记录都不是可以直接粘贴的成稿。引用之前先判断它要说明的事实，再用本站的句式重写。

- 不保留英文语序。英文习惯把条件放在主句之后、用从句层层修饰，中文应当先给结论，再补条件。
- 不逐词对应。`enable the feature` 写「启用该功能」，不写「使能这个特性」。
- 不保留原文的营销腔。`seamless`、`powerful`、`effortless` 这类词在中文文档里通常整句删掉。
- 不把口语直接落成正文。语音转写常见的重复、缺主语、语序倒置，都要按原意整理。
- 一个英文术语在同一页只解释一次。后面直接使用，不再重复括注原文。
- 引用上游文档的规则时写清出处，不把别人的约定说成我们的实现。

## 名称与术语

名称以[术语表](glossary.md)为准。产品名、协议名、界面名称和代码标识符分别处理：

- `DeepSeek Harness`、`AuraBot`、`TypeScript`、`Node.js` 等名称保留官方拼写和大小写。
- 中文正文中的按钮、菜单和配置项使用界面原文，并用中文引号标出。
- 文件名、目录名、字段、命令和代码符号使用反引号。
- 不在正文中随意切换「插件」「模块」「扩展」「应用」。它们不是同义词。
- 同一概念在同一页保持一致，除非正在解释版本差异。
- 首字母缩写第一次出现时应写出完整名称，例如「DeepSeek Harness（DSH）」。同一页后续直接使用缩写，不重复括注。
- 没有通行中文译名的技术名称保留英文，并在第一次出现时用一句话说明用途。不要自行创造生硬译名。
- 有通行中文名称的概念使用中文，不把英文原文当作装饰反复附在后面。
- 命令、函数、字段和类型名不翻译。解释文字使用中文，标识符保持原样。
- 中英文并用时，不在一句话中无必要地重复同一含义，例如不要写「插件（plugin）插件」。

### 术语的表述

| 场景 | 写法 |
| --- | --- |
| 缩写首次出现 | `DeepSeek Harness（DSH）` |
| 产品与版本 | `AuraBot V2`、`Node.js 22` |
| 技术标识 | `ctx.command()`、`package.json` |
| 没有通行译名 | 保留英文名称，并在首次出现时解释用途 |

术语表负责规定名称和版本口径。正文负责解释该名称在当前语境中的用途，两者不要互相替代。

## 全角与半角

中文正文使用全角标点，技术内容和英文文本保留半角字符。不要为了让版面看起来整齐而混用两套符号。

| 内容 | 使用 | 示例 |
| --- | --- | --- |
| 中文句子 | 全角标点 | `保存后重新启动，配置才会生效。` |
| 中文并列 | 全角顿号 | `账户、频道、权限` |
| 中文括号 | 全角括号 | `AuraBot（机器人框架）` |
| 中文引号 | `「」`，嵌套时用 `『』` | `打开「设置 → 模型」。` |
| 中文冒号 | 全角冒号 | `需要填写以下字段：` |
| 英文句子 | 半角标点 | `Cannot find module 'dsh'.` |
| 代码与命令 | 半角符号 | `pnpm install --frozen-lockfile` |
| 路径与 URL | 半角符号 | `src/index.ts`、`https://example.com/a?b=1` |
| 版本号 | 半角符号 | `1.2.0` |
| 界面原文中的标点 | 保持界面原样 | `File > Open` |

### 括号与引号

- 中文叙述中的补充说明使用全角括号：`AuraBot（运行在 DSH 中）`。
- 括号内是代码、路径、URL 或英文短语时，外层括号仍使用中文全角括号。
- 括号内侧不加空格：写 `（Node.js）`，不写 `（ Node.js ）`。
- Markdown 链接的 `()`、代码字符串的 `""`、命令参数中的引号属于语法或程序内容，不改成全角。
- 中文引号使用 `「」`，需要嵌套时使用 `『』`。不混用英文弯引号 `“”`。
- 引用第三方原文或界面原文时，可以保留原文符号，但应标明来源。

### 符号对照

| 场景 | 正确 | 错误 |
| --- | --- | --- |
| 中文逗号 | `先安装 Node.js，再启动服务。` | `先安装 Node.js, 再启动服务。` |
| 中文句号 | `配置保存后生效。` | `配置保存后生效.` |
| 中文顿号 | `指令、中间件、工具` | `指令, 中间件, 工具` |
| 中文冒号 | `需要填写三个字段：` | `需要填写三个字段:` |
| 中文分号 | `失败时记录日志；连续失败三次后停止。` | `失败时记录日志; 连续失败三次后停止。` |
| 中文括号 | `适配器（Adapter）` | `适配器 (Adapter)` 用于中文叙述时 |
| 中文引号 | `打开「设置」。` | `打开"设置"。` |
| 省略号 | `等待中……` | `等待中...` |
| 破折号 | `只有一条规则——不要改系统代理。` | `只有一条规则 -- 不要改系统代理。` |
| 范围连接 | `4 到 30 分钟` | `4-30 分钟`、`4~30 分钟` |

### 冒号、分号与破折号

- 中文说明句使用全角冒号 `：`，不要在中文冒号前加空格。
- 分句之间使用全角分号 `；`，不要用英文分号代替。
- 中文破折号使用 `——`，不要用连续的半角连字符模拟。
- 表示范围时使用「到」或统一的中文连接号，不混用 `-`、`~` 和 `至`。
- 代码、JSON、YAML、命令行和 URL 中的冒号、分号和连字符保持原样。

## 中英文混排

中文与英文单词、缩写、数字之间保留一个半角空格：

| 错误 | 正确 |
| --- | --- |
| 使用TypeScript编写 | 使用 TypeScript 编写 |
| 安装Node.js | 安装 Node.js |
| 等待3秒 | 等待 3 秒 |
| 最多10条 | 最多 10 条 |
| 配置API Key | 配置 API Key |
| 配置config.json | 配置 `config.json` |

以下情况不额外插入空格：

- 中文与全角标点之间：`保存后生效。`
- 数字与百分号组成百分比时：`50%`。
- 版本号、路径、URL、命令和代码表达式内部：`1.2.0`、`src/index.ts`、`ctx.command()`。
- 产品名本身带有的空格或连字符：`Node.js`、`QQ 空间`、`DeepSeek Harness`。
- 行内代码与中文之间已经有可见空格时，不再叠加第二个空格。写作时应保持为「运行 `pnpm build` 后检查」，而不是在反引号内外重复留白。

不要为了对齐而在汉字之间插入空格，也不使用全角空格或制表符排版正文。

判断是否需要空格，可以按顺序看三点：

1. 两侧是否都是中文。都是中文就不加。
2. 一侧是中文标点。中文标点自带间距，不加。
3. 一侧是英文单词、缩写或阿拉伯数字。加一个半角空格。

反引号内的内容整体视为一个英文单元，只处理它与外侧中文的交界，不改写内部。

### 数字、日期与单位

- 版本号按实际格式书写：`1.2.0`、`v24.8.0`。
- 技术数量使用阿拉伯数字：`3 个会话`、`10 条记录`。
- 数值与拉丁字母单位之间留一个半角空格：`50 MB`、`30 秒`、`8080 端口`。
- 百分比写作 `50%`，百分号前不留空格。
- 日期使用 `2026-11-25`，时间使用 `13:18`。正文需要自然语言时，可以写「2026 年 11 月 25 日」。
- 四位及以上计数需要分节时使用半角逗号，如 `10,000`。端口、状态码、版本号和代码中的数字不加分隔符。
- 范围使用「4 到 30 分钟」这类写法，单位和量词不要只写在一端。
- 小数使用半角小数点，如 `0.5`。代码、配置和版本号中的小数点保持原样。

## 标点与句子

- 一个句子表达一个主要意思。长句优先拆开，不用连续逗号堆叠条件。
- 中文句子以全角标点结束，英文句子以半角标点结束。
- 中文句子不要使用英文逗号 `,`、英文句号 `.` 或英文分号 `;`。
- 省略号使用中文省略号 `……`，不要在中文正文中使用三个半角句点。
- 问号和感叹号使用全角形式，不连续重复。
- 链接、行内代码和字段名前后的标点应与句子一起组织，不把句号放进链接文字。
- 引用界面文字时，引号包裹界面原文，句末标点放在引号外。
- 英文缩写后的中文标点按整句语言处理，不使用英文句点结束中文句子。

## 列表与表格

- 列表项目应保持相同语法结构。步骤使用动词开头的祈使句，属性使用名词短语。
- 列表项目如果是完整句子，末尾加句号；如果只是短语、名称或操作标签，不加句号。
- 同一列表内不要混用「完整句子」和「短语」两种形式，除非内容本身要求如此。
- 有序列表只用于有先后顺序的步骤。无顺序的并列内容使用无序列表。
- 列表项目内部需要补充说明时，优先拆成子段落，不堆叠多层缩进。
- 表格单元格使用短句或短语，通常不加句号。需要完整解释时，把说明移到表格下方。
- 表格列名不带末尾标点，列与列之间保持同一粒度。
- 表格中的代码、路径和字段名使用反引号，不要把反引号写在单元格分隔符外。

示例：

```md
- 检查配置文件。
- 重新启动服务。
- 查看启动日志。
```

这些项目都是完整动作，因此保留句号。只有名称的清单则不加：

```md
- `config.json`
- `logs/`
- `modules/`
```

## 界面元素与操作路径

界面名称统一用中文引号标注，保持界面原文，不翻译、不改写大小写：

| 内容 | 写法 |
| --- | --- |
| 单个按钮或菜单项 | `点击「保存」。` |
| 多级菜单路径 | `打开「设置 → 模型」。` |
| 配置项名称 | `在「最大重试次数」中填写 3。` |
| 输入框占位符 | `在「搜索」框中输入关键词。` |

- 多级路径使用 `→` 连接，箭头两侧各留一个半角空格，箭头本身不替换成 `>` 或 `-`。
- 界面路径整体放在引号内，不写成 `设置 -> 模型` 或 **设置 → 模型**。
- 界面元素不使用斜体。中文斜体渲染效果差，强调一律交给引号或粗体。
- 界面原文是英文时不翻译，例如 `点击「Save」。`；需要解释时在句外补充一句说明。
- 文档自身的文件名、目录名和字段名使用反引号，不使用引号，例如 `package.json`、`docs/guide/install.md`。

## 代码与命令

- 行内代码只放短名称和值，不用反引号强调普通词语。
- 多行命令按运行环境标记为 `powershell` 或 `bash`，不要把提示符 `$`、`>` 写进命令。
- 一条代码块只表达一个完整操作。需要替换的内容使用清楚的占位符，如 `<profile>`。
- 配置示例使用真实字段名。省略无关内容时，保证剩余内容仍是合法示例。
- 代码块前后的说明要与代码内容对应，不要求读者从注释推断步骤。
- 结构图使用 `<Diagram>` 和 SVG 组件；目录树、协议流程和纯文本输出使用 `text` 代码块。
- 命令中的参数、路径和引号保持程序要求的形式，不为了中文排版改成全角。

### 代码块语言

所有围栏代码块必须标注语言，符合 markdownlint `MD040/fenced-code-language`：

| 内容 | 语言标记 |
| --- | --- |
| PowerShell 命令 | `powershell` |
| POSIX shell 命令 | `bash` |
| TypeScript / JavaScript | `ts` / `js` |
| JSON / YAML | `json` / `yaml` |
| Markdown | `md` |
| 目录树、流程、日志、纯文本 | `text` |

## 链接

| 指向 | 写法 | 示例 |
| --- | --- | --- |
| 站内页面 | 相对当前文件，带 `.md` 后缀 | `[写作规范](docs-style.md)` |
| 跨目录页面 | 使用 `../` 定位，带 `.md` 后缀 | `[插件接口](../reference/plugin-api.md)` |
| 站外页面 | 完整 URL | `https://github.com/aureth-labs/dsh-aurabot-qq` |
| `public/` 静态文件 | 完整线上 URL | `https://aureth-labs.github.io/dsh-aurabot-qq-docs/llms.txt` |

站内链接必须使用相对路径并保留 `.md` 后缀，例如：

```md
[写作规范](docs-style.md)
[插件接口](../reference/plugin-api.md)
[平台连接](../guide/platforms/index.md)
```

不要使用 `/guide/install` 这类站点根路径。相对 `.md` 路径可以被 VS Code 的 Markdown 检查直接解析；VitePress 构建时会将其转换为对应的站内页面地址。

链接到目录首页时必须写出 `index.md`，链接到标题时在 `.md` 后追加锚点，如 `docs-style.md#链接`。

VitePress 不会为 `public/` 中的静态文件自动添加 `base`，因此不能只写 `/llms.txt`。

## 提示容器

VitePress 的自定义标题写在类型同一行，中间用一个空格分隔：

```md
::: warning V1 示例

这里是提示正文。
:::
```

标题只写一句短语，不换行、不带句号。把标题挪到下一行不会产生标题：VitePress 会把这一行当作正文，容器回退到默认的英文标题（`WARNING`、`Details`），在中文页面里会直接暴露出来。

需要多行说明时，标题保持一行，其余内容写在空行之后。`details`、`tip`、`info`、`danger` 的处理方式相同。

## Markdown 结构

- 每个标题前后保留空行，标题末尾不加句号。
- 标题层级按内容从 `##` 到 `###` 递进，不跳级。
- 段落之间保留一个空行，不使用连续空行制造间距。
- 列表、表格、代码块和提示容器前后保留空行。
- 不在正文中手写编号模拟多级列表，交给 Markdown 列表语法。
- 不为普通词语添加粗体、斜体或反引号。强调手段过多会降低可读性。
- 不使用原始 HTML 实现排版；需要图示时使用项目已有组件。
- 同一页只保留一个页面标题，章节标题不与页面标题重复。

## 准确性与版本

- 菜单、字段、默认值和限制必须有代码或已发布文档依据。
- 本机路径只能出现在明确标注为本机环境的示例中，不作为通用安装路径。
- 未验证的结论不写为事实。可以写「当前实现」「规划中」「待验证」。
- V1 的界面说明与 V2 的设计稿分开呈现，不用设计稿描述现有操作。
- 修复错误时同步检查站内其他页面，避免同一术语出现不同解释。
- 当前文档只提供简体中文版本。英文只用于产品名、协议、代码和技术术语，不作为翻译版本发布。
