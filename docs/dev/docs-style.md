# 写作规范

文档用于帮助读者完成具体操作。句子应当清楚、简短，不替产品宣传，也不重复同一结论。

## 文风

- 先说结论，再写条件和步骤。
- 一页只解决一类问题。背景、安装方法、配置说明和故障排查不要挤在同一页。
- 能直接说明事实时，不使用比喻、口号或反问。
- 不写「简单来说」「不难发现」「你一定遇到过」「赋能」「丝滑」「完美」「最佳实践」等空泛表述。
- 不用大量粗体制造重点。只有默认值、限制和容易误操作的地方需要强调。
- 列表中的项目采用相同句式。步骤写动作，表格写属性，说明文字解释原因。
- 页面顺序由侧栏决定，不在文末另写「下一步」或「延伸阅读」。
- 功能尚未实现时，明确写「规划中」或「待确认」，不使用确定语气描述设计稿。

| 不推荐 | 推荐 |
| --- | --- |
| 她的大脑，想聊就聊 | 模型服务负责生成回复 |
| 一句话记住，永不绕晕 | AuraBot 是 DeepSeek Harness 的插件 |
| 只需三步，丝滑上线 | 按以下顺序完成配置 |
| 不会让消息石沉大海 | 请求失败时记录错误并返回提示 |

## 名称与术语

名称以[术语表](/dev/glossary)为准。产品名、协议名、界面名称和代码标识符分别处理：

- `DeepSeek Harness`、`AuraBot`、`TypeScript`、`Node.js` 等名称保留官方拼写和大小写。
- 中文正文中的按钮、菜单和配置项使用界面原文，并用中文引号标出。
- 文件名、目录名、字段、命令和代码符号使用反引号。
- 不在正文中随意切换「插件」「模块」「扩展」「应用」。它们不是同义词。
- 同一概念在同一页保持一致，除非正在解释版本差异。

## 空格

中文与英文单词、数字之间留一个半角空格：

| 错误 | 正确 |
| --- | --- |
| 使用TypeScript编写 | 使用 TypeScript 编写 |
| 安装Node.js | 安装 Node.js |
| 等待3秒 | 等待 3 秒 |
| 最多10条 | 最多 10 条 |

以下情况不加空格：

- 中文与全角标点之间：`保存后生效。`
- 行内代码与相邻中文之间：`运行 pnpm install 后重启。`
- 连续的产品名、版本号、路径或代码表达式内部：`Node.js`、`1.2.0`、`ctx.command()`。
- 数字与中文量词、单位组成常用短语时，可按语义写作「三步」「两分钟」；技术参数仍写「3 秒」「20 MB」。

不要为了对齐而在中文之间插入空格。

## 标点

中文叙述使用全角标点：`，。；：？！（）「」`。代码、命令、路径、URL 和英文句子保留半角字符。

| 场景 | 写法 |
| --- | --- |
| 中文说明 | 打开面板，选择「模型」。 |
| 字段列表 | 包含 `url`、`sha256` 和 `size`。 |
| 英文错误原文 | `Cannot find module '...'` |
| 路径 | `src/index.ts` |

不要把代码中的半角逗号、括号、引号改成全角。链接文字与标点分开书写，句号不放进链接。

## 数字与单位

- 版本号按实际格式书写，如 `1.2.0`。
- 数值与拉丁字母单位之间留空格：`50 MB`、`30 秒`、`8080 端口`。
- 状态码、端口号和字段值使用反引号，如 `404`、`3001`。
- 范围使用「到」或连接号，全文保持一致，如「4 到 30 分钟」。

## 代码与命令

- 行内代码只放短名称和值，不用反引号强调普通词语。
- 多行命令按运行环境标记为 `powershell` 或 `bash`，不要把提示符 `$`、`>` 写进命令。
- 一条代码块只表达一个完整操作。需要替换的内容使用清楚的占位符，如 `<profile>`。
- 配置示例使用真实字段名。省略无关内容时，保证剩余内容仍是合法示例。
- 结构图使用 `<Diagram>` 和 SVG 组件；目录树、协议流程和纯文本输出使用 `text` 代码块。

### 代码块语言

所有围栏代码块必须标注语言，符合 markdownlint `MD040/fenced-code-language`：

| 内容 | 语言标记 |
| --- | --- |
| PowerShell 命令 | `powershell` |
| POSIX shell 命令 | `bash` |
| TypeScript / JavaScript | `ts` / `js` |
| JSON / YAML | `json` / `yaml` |
| Markdown | `md` |
| 目录树、流程、日志、纯文本 | `text` |

## 链接

| 指向 | 写法 | 示例 |
| --- | --- | --- |
| 站内页面 | 以 `/` 开头，不带 `base` | `/guide/install` |
| 站外页面 | 完整 URL | `https://github.com/aureth-labs/dsh-aurabot-qq` |
| `public/` 静态文件 | 完整线上 URL | `https://aureth-labs.github.io/dsh-aurabot-qq-docs/llms.txt` |

VitePress 不会为 `public/` 中的静态文件自动添加 `base`，因此不能只写 `/llms.txt`。

## 准确性与版本

- 菜单、字段、默认值和限制必须有代码或已发布文档依据。
- 本机路径只能出现在明确标注为本机环境的示例中，不作为通用安装路径。
- 未验证的结论不写为事实。可以写「当前实现」「规划中」「待验证」。
- V1 的界面说明与 V2 的设计稿分开呈现，不用设计稿描述现有操作。
- 修复错误时同步检查站内其他页面，避免同一术语出现不同解释。

## 提交前检查

- [ ] 用词符合[术语表](/dev/glossary)，产品名大小写正确。
- [ ] 中文标点、空格、数字和单位符合本页规范。
- [ ] 没有宣传口号、重复总结和无依据的承诺。
- [ ] 命令可直接执行，示例字段与当前代码一致。
- [ ] 所有代码块均标注语言。
- [ ] 站内链接和静态文件地址有效。
- [ ] `pnpm docs:build` 通过。
