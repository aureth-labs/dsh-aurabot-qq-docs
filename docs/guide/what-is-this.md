# 框架概览

AuraBot 是运行在 DeepSeek Harness（DSH）中的跨平台机器人框架。DSH 负责会话、模型和插件加载，AuraBot 负责消息处理、机器人实例与功能扩展。

本站面向 V2。V2 使用 TypeScript，插件通过 `apply(ctx, config)` 注册能力；现有 V1 的界面和模块接口只在兼容说明中保留。

## 消息处理

<Diagram caption="消息从进入到发送的处理顺序">
  <MessageFlow />
</Diagram>

AuraBot 同时提供确定性处理和模型生成：

- 指令适合格式明确、需要立即执行的操作。指令可直接触发，其处理和发送结果可以写回会话上下文。
- 中间件适合消息解析、内容改写和条件拦截。调用 `next()` 可将消息交给后续处理。
- 模型阶段适合需要理解语境的回复与工具调用。工具参数由模型生成，不直接作为用户指令使用。

默认处理顺序为「指令 → 中间件 → 模型」。指令消费消息后是否继续执行中间件，由全局配置决定；该配置仍在设计中。

## 与指令机器人的区别

| 对比项 | 指令机器人 | AuraBot |
| --- | --- | --- |
| 默认处理方式 | 匹配命令或关键词 | 支持指令，也可交给模型理解 |
| 扩展能力 | 注册命令处理函数 | 注册指令、中间件、工具和事件 |
| 回复依据 | 预先编写的规则 | 规则、会话上下文、人格和记忆 |
| 平台接入 | 通常与业务代码耦合 | 由适配器统一消息格式 |

两种机制可以共存。需要固定结果的操作走指令或中间件，需要语言理解的操作交给模型。
