# 这是什么

AuraBot 是一个**跑在 DeepSeek Harness 上的多平台 AI 框架**：把 QQ、Telegram、Discord 这些平台接进会话，
让模型直接决定说什么、做什么，而不是命中一条关键词再吐一段固定文本。

这份文档写的是 **V2**：主框架用 TypeScript 重写，插件改成 `apply(ctx, config)` 的写法，
平台通过适配器接入。V1 与 V2 的关系见[链接](/links)。

记住一句就不会绕晕：**插件住在框架里，框架住在 DSH 里**。
适配器和功能件都是插件，区别只是它们往 `ctx` 上注册的能力不同——一个注册平台，一个注册指令和工具。

## 生态位：跟传统机器人不是一类东西

传统指令机器人靠「正则命中 → 执行 handler」把功能穷举出来；AuraBot 默认把消息交给模型，
功能变成模型可以调用的工具。指令和中间件仍然在，但它们是给**确定的事**准备的快路径。

| 维度 | 传统指令机器人 | AuraBot |
| --- | --- | --- |
| 消息默认去处 | 指令表，没命中就丢弃 | 模型，由模型判断回不回、怎么回 |
| 加一个功能 | 写一个 handler，挂到匹配规则上 | 写一个插件，注册 `ctx.tool` / `ctx.command` |
| 谁做判断 | 开发者提前穷举 | 模型 + 你给的人格、记忆和工具 |
| 接一个新平台 | 改核心代码 | 装一个适配器插件 |
| 擅长 | 确定、高频、格式固定的任务 | 不确定的对话和需要理解语境的任务 |

所以两者不是替代关系：**确定的事交给指令，不确定的事交给模型**。QQ 群里两个都要，只是比例不同。

## 一条消息怎么走

<Diagram caption="实线是主链路，虚线是每一段的旁注">
  <MessageFlow />
</Diagram>

三段顺序是固定的：**指令 → 中间件 → LLM**。

- 指令是快路径：用户直接触发，不必等模型，结果照样写回上下文，模型下一轮看得到
- 中间件用来做解析和拦截，可以消费掉消息，也可以 `return next()` 往下传
- 到了 LLM 阶段，人格、记忆、上下文拼成提示词，模型可以选择直接回，也可以调 `ctx.tool` 干活

具体怎么写这几段，见[插件接口 v2](/reference/plugin-api)。

想看装起来要准备什么，从[准备](/guide/prepare)开始；想看它能干什么，直接翻[功能总览](/features/)。
