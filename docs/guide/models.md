# 配置模型

AuraBot 使用 DSH 中配置的模型服务。开始聊天前，需要确认模型请求能够正常完成。

## 连接模型服务

可以直接配置模型提供商，也可以通过模型网关接入多个提供商。需要模型路由、重试或故障转移时，推荐在模型网关中处理，避免在 DSH 中重复维护这些规则。

本站示例使用 [Magpie](https://github.com/yetone/magpie)。它是独立项目，不属于 AuraBot；安装和配置方法以 [Magpie 文档](https://usemagpie.ai/zh)为准。

在 DSH 中打开「设置 → 模型 → 添加模型提供商 → 自定义模型 API」，填写：

| 字段 | 内容 |
| --- | --- |
| Provider ID | 用于识别该提供商的固定 ID |
| 基础 URL | 模型服务的完整基础地址 |
| API 协议 | 与服务端一致的协议 |
| API Key | 对应服务的密钥 |
| 模型 | 至少一个有效的模型 ID |

保存后使用「获取可用模型」检查连接。直接连接提供商时，按 [DSH 官方文档](https://deepseek-harness.github.io/deepseek-harness/)填写对应配置。

## 选择默认模型

模型选择器设置的是**新会话的默认模型**。已有会话继续使用创建时记录的模型。

更换模型后，如需统一测试环境，可以删除旧会话再新建。删除会话不会删除 AuraBot 的记忆、人格和配置；这些数据单独保存在数据目录和数据库中。

AuraBot 中的模型配置读取 DSH 的提供商列表。先在 DSH 中验证请求，再调整 AuraBot 的模型选择。

## 错误排查

| 状态或现象 | 常见原因 | 检查方法 |
| --- | --- | --- |
| `400` | 协议、模型 ID 或请求字段不匹配 | 核对协议和模型 ID |
| `401` | 密钥无效或过期 | 更新密钥并重新保存 |
| `403` | 账号无权限、额度受限或地区受限 | 检查提供商后台 |
| `404` | 基础 URL 或模型 ID 错误 | 检查 `/v1` 等路径，重新获取模型列表 |
| `429` | 请求频率或额度达到限制 | 降低频率，检查额度 |
| `500` | 上游服务内部错误 | 更换模型或稍后重试 |
| `502` | 模型网关无法连接上游 | 查看模型网关日志 |
| `503`、`504` | 上游过载或请求超时 | 缩短输入，检查超时设置 |
| 不支持流式响应 | 服务端未实现所需协议 | 关闭流式响应或更换服务 |
| 长时间无响应 | 地址、端口或进程异常 | 请求模型列表接口检查连通性 |
| 空响应或内容截断 | 上游中断、输出上限过低 | 查看原始响应并调整输出上限 |

排查时分别测试模型服务和 DSH：直接请求成功而 DSH 失败，通常说明提供商配置有误；两处都失败，则先检查模型网关、密钥或上游服务。
