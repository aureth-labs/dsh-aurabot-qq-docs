# 配置模型

DSH 自己不产模型，它只把请求转发给你配的提供商。**我们不会替你默认选一个**——
装完必须自己挑，没挑之前她一句都说不出来。

## 用网关挂模型（推荐）

一台机器人要同时应付闲聊、长文、看图，很可能不止一个模型。把多家供应商收进一个网关，
DSH 里只填一个地址，换模型、加供应商、做故障转移都不用再动 DSH。

我们自己在用的是 [Magpie](https://github.com/yetone/magpie)：本地起一个 OpenAI 兼容入口
（默认 `http://127.0.0.1:3425/v1`），把各家模型挂在它下面。

::: warning Magpie 是独立项目
它不属于 AuraBot，也不由我们维护。装法和用法看
[Magpie 文档](https://usemagpie.ai/zh)，我们只提供这套组合的使用经验。
:::

接进 DSH 的方式：**设置 → 模型 → 添加模型提供商 → 自定义模型 API**，把网关地址、
协议（`openai-completions`）和密钥填进去，然后点「获取可用模型」把模型列表拉下来。

不想用网关也行，DSH 内置了常见供应商，填官方密钥即可；具体填法看
[DSH 官方文档](https://deepseek-harness.github.io/deepseek-harness/)，这里不重复。

## 选模型：只影响新会话

模型选择器里选中一个，等于**把它设成新会话的默认值**。已经在跑的会话保留自己日志里记的那个模型，
不会跟着变。

所以调完模型之后，建议**把已有会话都删掉**再开新的，否则你会看到「明明换了模型，回复还是老样子」。
删会话不会丢记忆：聊天记录落在数据库里，人格、长期记忆、人物档案都在数据目录，跟会话是两回事。

## 插件里的模型

框架装好之后，面板可以单独指定聊天用哪个模型、要不要按场景换模型。
它读的就是上面这套配置，所以先把 DSH 配好，再来调插件。

## 排错

先看报错码，再决定改哪儿。

| 现象 | 多半是什么 | 怎么办 |
| --- | --- | --- |
| `400` | 请求格式不对：协议选错、模型 ID 不存在、字段名不对 | 换 `API 协议` 再试；核对模型 ID 大小写 |
| `401` | 密钥错、过期，或该提供商要额外的 project / 账号 ID | 重填密钥；看是不是填到了别的提供商卡片里 |
| `403` | 密钥有效但没权限：没开通、地区限制、额度冻结 | 去供应商后台看额度与权限 |
| `404` | 路径不对：`baseURL` 少了 `/v1`，或者模型名拼错 | 补全地址；用「获取可用模型」确认真实 ID |
| `429` | 限流或额度用完 | 降频率、加余额，或换一个模型 |
| `500` | 上游内部错误 | 换模型；持续复现就是供应商的问题 |
| `502` | 网关连不上上游（bad gateway） | 网关到供应商这段断了，看网关日志 |
| `503` / `504` | 上游过载或超时（upstream timeout） | 稍后重试；长上下文任务调小输入 |
| `not upstream` / 提示不支持流式 | 网关不支持 SSE | 在提供商设置里关掉流式 |
| 一直转圈没响应 | 网关地址不通、端口写错、进程没起 | `curl <baseURL>/models` 通一下 |
| 返回空、或回复被截断 | 上游中断，或 `maxTokens` 太小 | 调大输出上限；看网关日志里有没有截断 |

定位手段只有一个：**同一份配置，先用 `curl` 直接打网关，再回 DSH 里试**。
`curl` 通而 DSH 不通，问题在 DSH 的提供商配置；两边都不通，问题在网关或密钥。
