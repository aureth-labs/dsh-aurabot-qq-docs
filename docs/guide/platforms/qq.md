# 接入 QQ

AuraBot 不直接和腾讯的服务器打交道，它连的是一个 **OneBot v11 网关**。
网关负责让机器人号上线，框架只负责「收到消息 → 想 → 发回去」。

```text
QQ ⇄ 网关（SnowLuma / NapCat / LLOneBot / Lagrange）⇄ AuraBot ⇄ DSH 会话
```

两条路线二选一，向导第 2 步就是选这个。

## 路线 A：SnowLuma（Windows 最省事）

SnowLuma 的协议不允许别的程序替你下载安装，所以下载解压要你自己来：

1. 点向导里的「打开下载页」，下载 `SnowLuma-v2.x.x-win-x64.zip`（**不带 lite** 的完整版）
2. 解压到一个纯英文目录，推荐 `C:\Aurabot\snowluma`。解压后目录里应该能直接看到 `index.mjs`
3. 回向导填目录，点「检查」，显示「找到了 SnowLuma」
4. 点「启动 SnowLuma」——后台运行，不弹黑窗口
5. 控制台密码由插件自动生成并保存
6. 读完协议，勾选「我已阅读并同意」
7. 另开 QQ 登录机器人号，点「接入机器人号」

插件**只给登录机器人号的那个进程注入**。点「看看有哪些 QQ 进程」能看到每个进程登的是哪个号，主号那行写着「不会碰」。认不出号时，只在唯一一个认不出号的进程上注入，连上后用 `get_login_info` 核对，不是机器人号就断开并撤销。

## 路线 B：接已有的 OneBot v11

NapCat、LLOneBot、Lagrange、Docker 版 SnowLuma 都行：

1. 在这些工具里开 **正向 WebSocket**（不是反向，也不是 HTTP）
2. 记下地址，形如 `ws://127.0.0.1:3001`，有 token 就一起记下来
3. 向导弹「接我已有的 OneBot 机器人」，填地址和 token

**插件只连接，不启动网关、不注入任何东西。** 连上后会先用 `get_login_info` 核对登录的是不是机器人号。

## Linux / Docker 三个坑

| 坑 | 怎么办 |
| --- | --- |
| 容器里填 `127.0.0.1` 连不上 | 容器里的回环是容器自己。填宿主机或另一个容器能访问到的主机名和端口 |
| 语音功能报缺依赖 | 装 `python3-venv` 或 [uv](https://docs.astral.sh/uv/) |
| 翻唱（RVC）用不了 | 目前只支持 Windows |

## 接上之后先别急着上线

默认是「总开关关 + 试运行开」，试运行只生成回复、不真的发到 QQ。先在「日志」页看她会怎么回，确认没问题再开总开关。

如果重启 DSH 后有一阵发不出消息，一般不用管：网关暂时连不上会自动等几秒重试；上一个 SnowLuma 还没退干净时会先等它释放端口，或者直接接着用它。刚连上那一会儿收到的消息也会补上。日志里看到「网关暂时连不上，…后重试」是正常的。

## 白名单别忘了

把机器人号拉进群之后，还要在「权限」页把**群号加进群白名单**。拉进群 ≠ 她会说话，
配置项的位置和含义见[认识面板](/guide/configure#白名单与权限)。

## 关于封号

用的是你自己的号和你自己选的网关，风险和你用其他 QQ 机器人框架一样。

| 该做 | 不该做 |
| --- | --- |
| 机器人用小号 | 拿主号当机器人 |
| 先试运行 | 一上来就开总开关群发 |
| 只和白名单里的人互动 | 高频打扰陌生人 |

## 排查

| 现象 | 怎么办 |
| --- | --- |
| 「QQ 网关」一直连不上 | 机器人号的 QQ 开着吗？QQ 重启过的话，回「连接」页点「接入机器人号」 |
| 「接入机器人号」说找不到 | 确认机器人号已经登录完成，等十几秒再点一次 |
| 她说 @ 了人但对方没收到提醒 | 她只认群名片和 QQ 昵称，认不出你手机上的备注。告诉对方群名片或 QQ 号 |
| 群里她不说话 | 群号在「群白名单」里吗？试试 @ 她 |
