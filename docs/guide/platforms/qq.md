# 接入 QQ

QQ 通过 OneBot v11 网关连接。QQ 网关负责账号登录和消息传输，AuraBot 使用协议提供的消息与事件。

```text
QQ ⇄ OneBot v11 网关 ⇄ AuraBot ⇄ DSH
```

可使用 SnowLuma、NapCat、LLOneBot 或 Lagrange。以下操作描述当前 V1 面板，V2 界面可能调整。

## 使用 SnowLuma

SnowLuma 的许可协议要求用户自行下载和安装：

1. 从向导打开下载页，下载完整的 Windows 版本。
2. 解压到纯英文目录，例如 `C:\Aurabot\snowluma`，确认目录中存在 `index.mjs`。
3. 在向导中填写目录并执行检查。
4. 阅读并同意协议后启动 SnowLuma。
5. 登录机器人账号，再执行「接入机器人号」。

插件只处理机器人账号对应的 QQ 进程。连接后通过 `get_login_info` 核对账号，不一致时断开连接。

## 连接现有 OneBot v11 服务

1. 在 QQ 网关中启用**正向 WebSocket**。
2. 记录地址和访问令牌，例如 `ws://127.0.0.1:3001`。
3. 在 AuraBot 向导中选择连接现有 OneBot 服务并填写信息。

此方式不会启动或修改现有 QQ 网关。

## Linux 与 Docker

| 问题 | 处理方法 |
| --- | --- |
| 容器中使用 `127.0.0.1` 无法连接 | 改为宿主机或其他容器可访问的地址 |
| 语音功能缺少 Python 依赖 | 安装 `python3-venv` 或 [uv](https://docs.astral.sh/uv/) |
| 翻唱不可用 | 当前 RVC 流程仅支持 Windows |

## 启用发送

新安装默认关闭总开关并开启试运行。先检查日志中的生成结果，再开启实际发送。

群聊还需要配置群白名单；将机器人加入群聊不会自动授予发言权限。相关配置见[面板配置](/guide/configure#白名单与权限)。

## 连接排查

| 现象 | 检查项 |
| --- | --- |
| QQ 网关未连接 | 机器人账号是否在线，WebSocket 地址和令牌是否正确 |
| 找不到机器人账号 | QQ 是否完成登录，稍后重新检查 |
| 群里没有回复 | 群白名单、总开关和试运行状态 |
| @ 没有提醒 | AuraBot 只能依据群名片或 QQ 昵称识别用户 |

使用机器人账号时，避免高频发送和打扰非白名单用户。账号与 QQ 网关均由用户自行选择和管理。
