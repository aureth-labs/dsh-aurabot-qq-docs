# 接入 QQ

AuraBot 通过 OneBot v11 服务接入 QQ。AuraBot 不负责 QQ 登录，也不启动或安装 OneBot 实现端。

```text
QQ ⇄ OneBot v11 服务 ⇄ AuraBot ⇄ DSH
```

请先自行准备可用的 OneBot v11 服务，并确认该服务能够正常收发 QQ 消息。AuraBot 不限定实现端；如果尚未选择，本文以 [LuckyLilliaBot](https://github.com/LuckyLilliaDev/LuckyLilliaBot) 作为示例。

## 连接现有 OneBot v11 服务

1. 在 OneBot v11 服务中启用**正向 WebSocket**。
2. 记录监听地址和访问令牌，例如 `ws://127.0.0.1:3001`。
3. 在 AuraBot 的连接配置中选择「连接现有 OneBot v11 服务」。
4. 填写 WebSocket 地址和访问令牌，保存后检查连接状态。

该方式只连接现有服务，不会修改其登录状态、协议配置或 QQ 进程。

## Linux 与 Docker

容器和远程部署只需要保证 AuraBot 能访问 OneBot v11 服务：

| 场景 | 配置 |
| --- | --- |
| Docker 容器访问宿主机服务 | 将 `127.0.0.1` 改为宿主机在容器网络中可访问的地址 |
| AuraBot 与 OneBot 服务位于不同容器 | 使用同一容器网络，或填写对方容器可解析的主机名 |
| 远程主机 | 确认 WebSocket 监听地址不是仅本机可访问的回环地址，并按需配置防火墙与访问令牌 |

OneBot v11 服务的安装、登录和运行参数以对应项目文档为准。

## 启用发送

新安装默认关闭总开关并开启试运行。此时可以查看生成结果，但不会向 QQ 发送消息。

**群白名单是全局配置项。只有加入白名单的群聊才会被处理并允许发送消息；把机器人拉进群聊不会自动获得发言权限。**

启用前至少完成以下检查：

1. OneBot v11 服务在线，机器人账号状态正常。
2. 群号已加入全局群白名单。
3. 总开关已开启，试运行按需要关闭。
4. 在目标群中发送一条测试消息，确认能够收到回复。

## 连接排查

| 现象 | 检查项 |
| --- | --- |
| 连接失败 | WebSocket 地址、端口、访问令牌和服务监听地址 |
| 找不到机器人账号 | OneBot v11 服务是否完成 QQ 登录 |
| 群里没有回复 | 群号是否在全局白名单中，以及总开关和试运行状态 |
| @ 没有提醒 | 服务提供的用户标识和群名片是否可读取 |

账号、协议端和网络环境均由用户自行选择与管理。请遵守平台规则，避免高频发送或打扰未授权用户。
